00概述 · OVERVIEW

一条船，
把影像载到每块屏幕上。

映舟是一个兼容 TVBox 配置与蜘蛛协议的全平台影视客户端。TVBox 的订阅生态很大，能好好用它的地方却几乎只有安卓；映舟把它带到 Windows、macOS、手机、平板和电视上，并且在每一种设备上，都按那种设备的习惯来操作。

做法是一个引擎、一个客户端、一套协议：Kotlin 引擎负责订阅、蜘蛛、解析和缓存，Flutter 客户端负责界面与播放，中间是 HTTP。所以引擎可以装进桌面安装包，装进安卓 App，也可以住进 NAS。

它只是播放器外壳：不内置、不提供任何影视内容或订阅源。
本册范围：产品定义 · 架构 · 引擎 · 客户端 · 品牌 · 打包与发布。开源于 AGPL-3.0。

同一套代码，按设备形态换布局和操作方式；播放内核都是 libmpv。

桌面：开箱即用

安装包里带着引擎和裁剪过的 JRE，客户端启动时自己把引擎拉起来，退出时一起收走。不用装 Java。

安卓：引擎住在 App 里

引擎编进应用，ART 直接加载蜘蛛的 dex；前台服务让它在后台继续缓存、下载和共享。

NAS：一个引擎，全家的屏幕

引擎做成 Docker 镜像，局域网里的客户端配对后共用；远处的引擎只管解析，播放器直连片源。

08工程 · ENGINEERING

几件不那么显然的事。

01 · JAR ON DESKTOP

在桌面 JVM 上跑安卓蜘蛛

订阅里九成站点是为安卓写的 jar。引擎在进程内把 dex 转成 class，补上安卓桩类，再修掉转换留下的字节码问题；打包时用带自检的精简 JRE。

02 · THREE RUNTIMES

三种蜘蛛，三个运行时

jar 走 DexClassLoader 或 dex2jar，JavaScript 走 QuickJS，Python 走独立的工作进程。不捆绑 Python：用系统里的，或者由用户点一下再下载。

03 · SNIFFING

嗅探放在引擎一侧

要从网页里找出视频地址时，桌面用无头的 Edge / Chrome（DevTools 协议），安卓用 WebView。客户端不用关心片源是怎么来的。

04 · STREAMS

m3u8：去广告与播放缓存

播放列表经引擎清洗后再交给播放器，分片缓存在磁盘上，拖动进度条立刻有画面；连着远处的引擎时，播放器改为直连片源。

05 · ONE CODEBASE

一套代码，四种手感

设备形态（桌面、手机、平板、电视）是界面里的一等概念：同一个页面按形态换布局、换手势层、换焦点规则，而不是四个应用。

06 · DEFAULTS

会把数据交给第三方的，默认关

GitHub 加速、DoH、订阅自带的弹幕接口，都是开关且默认关闭。体检工具没被要求时，不会注册任何蜘蛛运行时。
