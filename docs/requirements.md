# 需求

> 这份文档记录产品是什么、给谁用、守哪些原则，以及已有功能的清单。接下来做什么、先后顺序见 [roadmap.md](roadmap.md)，怎么做见 [architecture.md](architecture.md)，做到哪了见 [status.md](status.md)。

## 1. 背景

TVBox（影视仓）是 Android 上的影视聚合壳：用户填一个订阅地址，壳按配置里的站点、蜘蛛（jar / js / py）、解析接口、直播源去取内容并播放。它只有 Android 版，界面是为遥控器做的。

桌面上的替代品各有问题。以 Win-box（Electron）为例：内存占用大、多窗口、播放器靠 `mpv --wid` 叠在窗口上、dex 转换慢、JS 宿主函数不全（drpy 跑不了）。

## 2. 目标

做一个**兼容 TVBox 配置与蜘蛛协议**的新客户端，三个要求：

1. **兼容**：安卓版能用的订阅，这里拿来就能用。订阅链接、加密配置、多仓、type 0/1/3/4 站点、jar / js 蜘蛛、解析接口、嗅探、去广告规则、直播源都要认。
2. **界面现代、交互友好**：单窗口，鼠标键盘是一等公民，流式聚合搜索，自动换线路，续播。
3. **功能强**：直播 + 节目单、弹幕、多设备同步进度等，逐步补齐。

## 3. 用户与平台优先级

| 优先级 | 平台 | 说明 |
|---|---|---|
| **1** | **Windows** | 主要使用场景，所有功能先在这里做完并在真实应用里验证 |
| **2** | **macOS** | 与 Windows 同一份代码；CI 出 Apple Silicon 的 DMG，2026-11-20 在真机上试过 |
| 3 | NAS / Docker | 引擎单独部署，给局域网里的设备用 |
| 4 | iOS / iPadOS | 先做纯客户端，连局域网里的引擎；本机轻引擎在调研（见 [roadmap.md](roadmap.md#ios)） |
| 5 | Android 手机 / 电视 | 2026-11-19 起和桌面一起做：手机 / 平板触屏界面、电视遥控器界面，内置引擎补齐播放缓存、离线下载、局域网共享 |
| 6 | Linux 桌面 | 2026-11-20 起出 x64 的 deb 和 tar.gz（Ubuntu 24.04 / Debian 13 起），只在 CI 的虚拟屏幕上验证过 |

> 2026-11-12 的决定：**桌面优先**。Android 已经有原版可用，本项目的价值在 Windows / Mac。
>
> 2026-11-19：桌面版功能做齐（v0.2.0）后开始做安卓，手机和电视一起做；APK 用正式签名密钥签名，随 GitHub Release 发布。

## 5. 非功能需求

- **许可证 AGPL-3.0**：会移植 TVBoxOS / Box（AGPL-3.0）的实现，所以整个项目是 AGPL。参考 Win-box（MIT）的部分保留其版权声明，见 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)。MisaTV 是 GPL-3.0，只看思路，不搬代码。
- **不内置内容**：只是播放器外壳，不带任何订阅或影视内容。
- **默认只监听本机**：引擎默认 `127.0.0.1`，要给局域网用必须显式打开。
- **开箱即用**：桌面包自带引擎和精简 JRE，用户不需要装 Java。
- **资源占用**：比 Electron 方案轻；不用的功能不占资源（如直播播放器在第一次打开直播页时才创建）。
- **最低系统**：Windows 10；Android 7.0（API 24，引擎因此不用 `java.time` / `java.util.Base64`）。

## 6. 约束与约定

- 一个引擎、一个客户端、一套协议：TVBox 协议的细节只在引擎里，客户端只消费规整后的数据。
- 开发与测试只用演示数据和自己造的 jar，不在开发机上执行第三方蜘蛛 jar。
- 每个迭代本地提交；代码在 https://github.com/Sa1koro/yingzhou（公开），推送和打标签发版由使用者决定。
