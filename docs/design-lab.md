# 设计工作流：设计台与流程分镜

> 界面和交互怎么设计、怎么验证。两件工具都在仓库里：**设计台**把真实应用的四种设备形态并排摆开、可以直接操作、改代码热重载；**流程分镜**把一个任务在真实应用里走一遍，数出每一步，画成图。

## 原则

1. **先任务，后界面。** 先写清楚"谁、要干什么、几步做完"（例如"电视上从首页到开始播放"），再画界面。步数和等待是硬指标，不是感觉。
2. **先设计系统，后页面。** 颜色、字号、间距、圆角、动效、焦点样式先定成一套 token，页面只用 token。没有设计系统时，生成的界面只会是框架默认的样子。
3. **在最便宜的地方迭代。** 新流程（比如简单模式、开发者模式）先在可以随手改的原型里试几轮——Claude 的 Design 画布、Whiteboard 或 HTML 原型，几分钟一版，可以在上面评论；方向定了再写 Flutter。
4. **在真实应用里验证，并且量化。** 写成 Flutter 之后，用设计台看四种设备、浅色深色；用流程分镜数步数、看等待。
5. **AI 做执行和评审，人做取舍。** 让 Claude 按下面的审阅清单看截图和分镜、提修改方案、直接改代码；要不要这样改由人决定。

## 设计系统

映舟的设计语言叫「夜航」：界面是夜里的水面，安静、往后退；海报和画面是亮处；船身的珊瑚色只出现在要按的地方；三色水纹只表示「流」（进度、加载、多条线路）。完整的规则（语气、颜色、字、间距、形状、焦点、动效、图标、四种设备）在 [design/system/README.md](design/system/README.md)，十个组件各有说明和预览页（`design/system/components/<组件>/`）。

- **唯一的来源**是 [design/tokens.json](design/tokens.json)：两个主题（夜 / 晨）的 24 个颜色、字号、间距、圆角、阴影、尺寸。每个文字颜色在它说明里写的底色上都不低于 4.5:1。
- 改了它就运行 `node tools/design/gen-tokens.mjs`，生成 `client/lib/ui/yz_tokens.dart`（不要手改），热重载。主题在 `client/lib/ui/theme.dart` 里只用这些 token；页面里要拿颜色时用 `YzTokens.of(context)`，长度用 `Yz.space4` 这类常量。
- 设计台顶栏的「主题」可以切到「旧版」，和改之前并排对比。
- 已经落到应用里的：配色（两个主题）、按钮、标签、输入框、导航（去掉胶囊高亮，当前项变珊瑚色加水纹）、分类标签下的水纹、海报圆角、侧边导航和电视导航顶部的标志。
- 还没做的：片名和页名的宋体（需要随应用打包 Noto Serif SC 的常用字子集，现在都还是黑体）、水纹进度条、WaveLoader、提示条的新样式、焦点框统一成 3px 实线。

## 设计台

真实应用的四份完整副本并排：桌面 1440×900、手机 393×852（可加横屏）、平板 1180×820、电视 960×540。每一份都有自己的状态（设置只在内存里，不碰真正的应用），连同一个引擎；可以点、可以用键盘和方向键操作，和应用里一样。

```bash
# 先开一个引擎：演示引擎（.claude/launch.json 的 demo-engine，端口 19978），或 tools/promo 的宣传用片源
cd client
flutter run -d windows -t lib/design_lab/main.dart
```

- 改任何页面的代码，在终端按 `r` 热重载，四份同时更新——同一处改动在四种设备上的样子一次看全。
- 顶栏：换引擎地址、选设备、浅色 / 深色、缩放、全部重置、截图（存到"下载"文件夹）。
- 播放器的全屏会让整个设计台全屏，按 Esc 退出。
- 脚本用法（给评审出图）：`--dart-define=LAB_SHOT=<文件.png> --dart-define=LAB_EXIT=true` 加载完存一张整幅截图后退出；`LAB_FRAMES=desktop,phone,tablet,tv,phone-landscape`、`LAB_THEME=light|dark`、`LAB_ZOOM=0.5` 控制其余。

## 流程分镜

`client/integration_test/flows_test.dart` 里每个测试是一个任务，按用户的操作来写：

```dart
final f = FlowRecorder(tester, id: 'tv-play', title: '电视：从首页打开一部片并播放', form: DeviceForm.tv, size: const Size(960, 540));
await f.start(ready: find.text('星河往事 第二季'), screen: '首页');
await f.press(LogicalKeyboardKey.arrowRight, screen: '首页 · 焦点进入内容区');
await f.press(LogicalKeyboardKey.enter, screen: '详情');
await f.waitFor(playButton, label: '详情加载', screen: '详情');
f.finish();
```

- `press`（按键）、`tap`（点按）、`type`（输入）、`hover`（移动鼠标）各算一步；`waitFor` 是应用在忙，记时间、不算步数。
- 每一步都截图；`screen` 是这一步之后所在的界面，同一个界面上的连续操作在图里合成一条箭头（"→ ×3"）。

```bash
cd client
flutter test integration_test/flows_test.dart -d windows --dart-define=FLOW_DIR=<目录>
node ../tools/design/storyboard.mjs <目录>     # 生成 <目录>/index.html，用浏览器打开
```

分镜页上每个流程有：总步数（按键、点按、输入各几下）、应用等待的总秒数、一张 Mermaid 流程图、一条每步截图的胶片。

## 一次迭代怎么走

1. 写或改一个流程测试，跑出分镜，记下步数和等待。
2. 在设计台里改界面，热重载，四种设备一起看。
3. 再跑分镜，对比步数；用设计台的脚本用法出整幅截图。
4. 截图和分镜交给 Claude 按审阅清单评审，挑要改的，回到第 2 步。

## 审阅清单

- **步数**：常用任务各有预算，超了就要说明为什么。建议的起点：电视从首页到开始播放不超过 4 下；手机搜索到播放不超过 4 步；任何设置项不超过 3 层。
- **第一眼**：每个界面最重要的一件事是什么？它是不是最大、最先看到的？有没有和它抢注意力的东西？
- **信息量**：这个界面上有多少个可点的东西、多少行字？哪些可以收起、合并或换到别处？
- **默认值**：用户什么都不选时，结果是不是已经对了（自动换线、自动选可用的站点）？
- **出错时**：说人话、给下一步（"已换到下一条"），不出现错误码和网址（开发者模式除外）。
- **三种手感**：同一个功能在键鼠、触屏、遥控器上各自顺不顺；电视上焦点从哪里开始、会不会丢、返回键回到哪。
- **一致性**：颜色、字号、间距、圆角、图标是否都来自设计系统。

## 第一次跑分镜发现的

| 流程 | 步数 | 发现 |
|---|---|---|
| 电视：从首页打开一部片并播放 | 5（按键 5） | 焦点从左侧导航开始，要按三下方向键才落到第一张海报 |
| 手机：搜索一部片并播放 | 5（点按 4、输入 1） | 搜索结果的前排来自"演示失效站"（线路都坏的那个演示站），点进去会放不了；结果应该按站点能不能用排序，或者直接把同一部片合并成一张卡片 |
| 桌面：播放中换一条线路 | 5（点按 4、移动鼠标 1） | 换线路藏在「选集」面板里，还要先动鼠标让控制条出来 |

## 为什么自己做，而不用现成的

现成的同类工具：Widgetbook（Flutter 版的 Storybook，组件和页面目录、参数旋钮、设备外框）、device_preview（在应用里模拟各种设备）、截图对比测试（golden 测试一类）、Figma 或 Penpot 加 Tokens Studio（设计稿和 token 导出成代码）、FlutterFlow 一类的可视化搭建（适合从零做新应用，不适合改已有的代码库）。Flutter 自己的 DevTools 可以点选界面上的组件、看布局。

映舟要的是：四种设备形态并排，其中电视要真的按遥控器的规则走焦点；页面连真实的引擎和数据；流程要能数步数。这几样现成工具都要绕一圈才做得到，而设计台只是在应用外面套一层，几百行代码。Widgetbook 以后可以用来做组件目录，和设计台不冲突。

"把 Flutter 导出成可以直接拖拽修改的编辑器"在已有代码库上还没有成熟可靠的做法（改完要能写回 Dart 代码）；现实的版本就是上面这条路：在设计台里看和操作，改动由人或 Claude 写进代码，热重载立刻看到。
