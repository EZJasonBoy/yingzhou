# 界面与交互梳理：用法、遥控器、网页控制台

> 2026-11-22 的一次梳理：用户反馈加上代码里查到的原因。每一节按「现状 → 原因 → 方案」写，最后是先后顺序和验证办法。做完一项就在这里标出来，并在 [status.md](../status.md) 里记验证情况。
>
> 从这次梳理里定下的规则在[设计系统的「交互：七条规则」](system/README.md)；排进下一版的两件事各有一页设计说明：[线路体检](line-probe.md)、[网页控制台](web-console.md)；拨盘和控制台的样子在[原型](prototypes/README.md)里。

## 一条原则：用法只改默认值，不拿走能力

三种用法（简单、标准、开发者）现在的做法是"简单模式把东西藏掉、开发者模式把东西加上"。结果两头都不对：

- 简单模式藏掉的恰好是片源不稳时最需要的东西（选线路、看为什么卡）；
- 好用的起始页只给了简单模式，开发者和标准模式反而没有。

改成：**每种能力在每种用法里都够得着，用法只决定它摆在第一层还是第二层、默认开还是关、说人话还是给细节。** 判断标准：简单模式的用户遇到"这条线路卡"时，不需要进设置、不需要输密码，在播放页就能换。

## 1. 用法

### 1.1 省心的起始页只有简单模式有（已做，2026-11-22）

**现状**：简单模式的首页第一个标签是「继续看」（上次那部片 + 一个接着播的大按钮，下面是最近看过和收藏，`simple_home.dart`）。标准和开发者模式一打开就是站点的推荐页，想接着看要去「我的」里找。

**方案**：把「继续看」从简单模式里拿出来，变成所有用法都有的首页标签；另加一个设置「打开映舟时先显示」：

| 选项 | 说明 |
|---|---|
| 继续看（默认） | 有观看记录时停在「继续看」，没有时停在站点推荐 |
| 站点推荐 | 现在标准模式的样子 |
| 我的 | 直接进「我的」（历史、收藏、下载） |

简单模式的默认值不变；标准和开发者模式也默认「继续看」。代码上就是把 `BrowsePage(simple:)` 里和「继续看」有关的部分改成看这个设置，而不是看用法。

**已做**：「继续看」是所有用法的首页第一个标签；「设置 → 外观 → 打开映舟时先显示」三选一（`StartPage`，`ui/user_mode.dart`；简单模式没有「我的」这个入口，所以只有前两项），下次打开时生效。顺带修了一个会被它撞上的问题：应用一打开就在「我的」时，引擎还没连上，「我的」不加载，连上以后也一直转圈。

### 1.2 简单模式选不了线路，也看不到统计和链路（线路和播放信息已做，2026-11-22）

**现状**：

- 详情页在简单模式下不列线路（`detail_page.dart`），播放页只有在全部失败、出现错误时才给「换线路」（`_linesOffered => !_simple || _error != null`）。
- 统计和链路只在开发者模式出现。
- 线路坏了时程序自己一条条换：每条线路最多等 15 秒才算失败（`_startTimeout`），一条接一条地试；简单模式的提示只有一句"这条线路打不开，已换到下一条"，不说是第几条、还剩几条。五条线路都慢，用户就得干看一分多钟，什么也做不了。

**方案**：

- **线路在所有用法里都能选。** 简单模式叫「线路 1、线路 2…」（站点起的名字常常是"超级无敌4k"这种，对长辈没意义），旁边显示测速结果（见 1.3）；详情页一行，播放页在拨盘的「线路」里（见 2.2）。手动选了的线路照旧不自动换。
- **「播放信息」在所有用法里都有**，放在播放页拨盘的「信息」里：
  - 简单 / 标准：一张卡片：清晰度、网速、缓冲了多少秒、正在用哪个站点哪条线路、刚才换过哪些线路以及为什么。全是人话。
  - 开发者：现在的完整统计和链路面板，外加复制为 curl / mpv 命令。
- **换线路时不再干等**：播放页中间显示一张"正在换线路"的卡片，列出每条线路的状态（✓ 能播 · 测速中 · ✗ 打不开），焦点在「选一条」上，用户随时可以自己挑或者「停在这里」。

**已做**：

- 线路：简单模式的详情页、播放页的选集面板（桌面、电视、手机）都列出线路，叫「线路 1、线路 2」；只有一条时不显示这一行；换线的提示从"这条线路打不开，已换到下一条"改成"线路 1 打不开，已换到线路 2"；遥控端看到的线路名和屏幕上一致。
- 播放信息（`pages/player_info.dart`）：每种用法都有。桌面在控制栏的 ⓘ，电视在「设置」面板（菜单键）里，手机在操作栏。内容是一句判断（很顺 / 够用 / 快见底了，可能会卡 / 正在缓冲，按缓冲了多少秒）、画面（1080p、帧数）、网速、硬件还是软件解码、掉帧、来自哪个站点、哪条线路、这一集换过哪些线路和原因、一句"总是卡怎么办"，和「换线路」按钮。没有网址，没有毫秒。开发者模式多两个按钮：完整统计、片源从哪来。
- 「正在换线路」卡片随线路体检一起做了（`pages/player_switching.dart`）。

### 1.3 线路体检：先测，再播（已做，2026-11-22；设计说明见 [line-probe.md](line-probe.md)）

现在是"播了才知道坏"。改成详情页一打开就在后台测这一集的各条线路，播放时直接挑最好的那条。

**怎么测**（引擎做，因为代理、请求头、解析都在引擎这边）：

1. 新接口 `POST /api/v1/play/probe`：给站点、片和集，按线路逐条解析出播放地址（复用 `/play/resolve`），结果按完成顺序流式返回。
2. 每条线路：取 m3u8（或文件头），记下能不能打开、首字节耗时、清晰度（m3u8 里的 `RESOLUTION`）；再下第一个分片的前几百 KB 估网速。
3. 限制并发（同时 3 条）和总时长（8 秒，超时的标"慢"不标"坏"）。jar / js 站点的解析会真的跑蜘蛛的 `playerContent`，所以只测当前这一集，不测整部。
4. 结果在引擎里缓存几分钟：换集时同一条线路的结论可以沿用。

**怎么用**：

- 线路按钮上显示 `1080p · 3.2 MB/s`、`慢`、`打不开`。
- 「播放」默认挑能打开、清晰度够、网速最快的那条；自动换线时跳过已知打不开的，并把 15 秒的等待缩短到测出来的情况（测出来是好的才给足时间）。
- 开发者模式另有一张线路对比表（路线图里已有这一条）。

## 2. 大屏和遥控器

目标：**用最少的按键、最固定的肌肉记忆完成任何操作。** 同一个键在同一种状态下永远做同一件事；一次只有一层能拿到焦点。

### 2.1 播放页的焦点会跑出面板（bug，已修，2026-11-22）

用测试里的遥控器按键复现（`tv_player_test.dart` 的同一套设置，1920×1080 电视）：

| 打开的面板 | 按键 | 结果 |
|---|---|---|
| 设置（菜单键） | ← | 焦点离开面板回到画面上，**再按 ← 就在面板后面快退**（面板还开着，进度在变） |
| 设置 | ↓ 到底再按 | 焦点落到控制栏的「弹幕」按钮上，面板还开着 |
| 选集（↑） | ← | 同上：离开面板，接着快退 |
| 选集 | ↓ / ↑ 到头再按 | 落到控制栏的「播放 / 暂停」、顶栏的「返回」上 |
| 字幕与音轨（从设置进入） | 打开时 | 焦点没进面板；按 ↓ 落到「播放 / 暂停」；按 ← 回到画面后再按 ↑，**又打开了选集面板，两个面板叠在一起** |
| 控制栏（↓） | → 到最右再按 | 离开控制栏，开始快进 |

这就是"开着设置、选集、链路时焦点还在进度条上"和"幽灵焦点"：焦点要么落在被面板盖住的按钮上，要么落在已经淡出看不见的控制栏按钮上，要么回到画面上让方向键去调进度。

**原因**（`player_page.dart`、`player_tv.dart`、`player_tracks.dart`）：

1. 面板（`PlayerSidePanel`）和控制栏是同一个 `Stack` 里的兄弟，面板没有自己的焦点范围，方向键的默认遍历会走到面板外最近的可聚焦控件。
2. 控制栏淡出（`AnimatedOpacity` + `IgnorePointer`）或被面板盖住时，它的按钮仍在焦点树里。`IgnorePointer` 只挡鼠标和触摸，不挡焦点。
3. `_onTvKey` 把"焦点不在画面上"一律当作"在面板或控制栏里"，交给默认遍历；焦点一旦回到画面，即使面板还开着，←/→ 也按"没有屏显"去调进度、↑ 也会再开一个面板。
4. 面板之间没有互斥：`_panelOpen`、`_tracksOpen`、`_danmakuOpen`、`_chainOpen`、`settingsOpen` 是五个独立的开关。

**修法**：

- 用一个状态代替五个开关：`无屏显 / 信息条 / 拨盘 / 面板（哪一个）`，同一时刻只有一个。
- 只有最上面那一层能拿焦点：面板在自己的焦点范围（`FocusScope`）里，方向键到边上就停；控制栏在电视上也是一个焦点范围，隐藏或被面板盖住时包 `ExcludeFocus`。
- 关面板时焦点回到打开它的地方（拨盘做好之前是画面）。
- 测试：每个面板四个方向各按到头再多按几次，焦点始终在面板里、进度不变、面板只有一个。

**已修**：五个开关合成一个 `_panel`（`player_page.dart`）；面板放在播放页的焦点范围里，并且每个面板自己是一个 `TvFocusLayer`（`tv_focus.dart`：打开时焦点进去，里面还没有能拿焦点的东西时先停在面板本身）；控制栏是 `_tvBars`；万一焦点还是不在面板里，`_onTvKey` 把它放回面板，这一下不做别的。测试在 `tv_player_test.dart`（"the focus stays in the panel or the bar that is open, at every edge"），在修改前的代码上会失败。到边上是"停住"而不是"收起面板"：收起交给返回键，按多了不会意外关掉。

### 2.2 播放页按键重新分配：拨盘（已做，2026-11-22）

参考相机和显示器的五向摇杆：**第一次按是"叫出菜单"，再按是"在菜单里走"，OK 是"进去调"，返回是"一层层退出"。** 电视上的控制栏不再放按钮，只显示信息，焦点问题从根上少一大半。

**按键表**：

| 状态 | ← / → | ↑ / ↓ | OK | 菜单键（或长按 OK） | 返回 |
|---|---|---|---|---|---|
| 无屏显 | 快退 / 快进 10 秒，按住加速（现在的做法） | 叫出拨盘，停在上次用的那一项 | 暂停 / 继续，并显示信息条 | 打开「播放设置」整页 | 显示"再按一次退出"，2 秒内再按才退出 |
| 拨盘 | 直接调这一项的值（见下表） | 换一项 | 进入这一项的面板 | 打开「播放设置」整页 | 收起拨盘 |
| 面板 | 在面板里走；到左边缘收起面板 | 在面板里走 | 选中 | 打开「播放设置」整页 | 回到拨盘 |

**拨盘上的项**（竖排在左边，每项右侧直接显示当前值；顺序可以在设置里调，简单模式少几项）：

| 项 | ← / → 直接调 | OK 进去 |
|---|---|---|
| 选集 | 上一集 / 下一集 | 选集面板（线路在上，集在下，焦点在正在播的那集） |
| 线路 | 换上一条 / 下一条 | 线路面板（每条的测速结果） |
| 倍速 | 0.5 ↔ 3.0 逐档 | 倍速面板 |
| 字幕 | 在字幕之间轮换（含"关"） | 字幕与音轨面板（偏移、大小、外挂字幕） |
| 弹幕 | 开 / 关 | 弹幕设置（密度、透明度、屏蔽词、弹幕源） |
| 画面 | 比例轮换 | 画面面板（比例、缩放，以后的画质增强） |
| 信息 | 开 / 关常驻的播放信息 | 播放信息与链路（见 1.2） |

这样原来控制栏上的「弹幕开关」「弹幕」「统计」「链路」四个按钮收进两项。重复上一次的操作只要两下（↑ 叫出停在上次那项，← / → 调）。

**时钟**：「播放设置」里加一项「屏显时间」：关 / 随屏显出现（默认）/ 一直显示在角落（小字、半透明）。信息条和拨盘出现时右上角显示当前时间和"本集还剩 xx 分钟，约 22:40 看完"。

**没有菜单键的遥控器**：很多电视盒子的遥控器没有菜单键，所以「播放设置」同时挂在长按 OK 上，拨盘最后一项也是「更多设置」。

**原型**：[prototypes](prototypes/README.md) 里「电视播放页：拨盘」一排五块画板：信息条、拨盘、拨盘进到线路、拨盘进到播放信息、正在换线路。和上面的文字有出入的地方以原型为准：拨盘是七项（选集、线路、倍速、字幕、弹幕、信息、更多设置），画面比例和音轨、屏显时间一起收进「更多设置」；面板紧挨着拨盘向右展开（不再贴着屏幕右边），在面板里按 ← 回到拨盘。

### 2.3 其他大屏页面

- 这次只复现了播放页。别的有叠层的地方（直播页的频道列表和节目单、右侧弹出的站点列表、对话框）也按 2.1 的规则各按到头试一遍：只有最上面一层能拿焦点。
- 进入页面时焦点落在"最可能要按的那个"上（从播放页回来落在刚看的那集，设置页落在上次改的那一项）。大部分页面已经这样，逐页核对一遍。

## 3. 网页遥控器和网页控制台

### 3.1 一开始播放，方向键就被挤下去（bug，已修，2026-11-22）

**现状**：网页遥控器（`engine/api/src/main/resources/remote/index.html`）里「正在播放」那张卡片（片名 + 进度条，`#now`）排在方向键上面，平时隐藏；一开始播放它就出现，把方向键整体往下推。屏幕上有输入框时出现的输入条（`#text-bar`）也一样。应用里的「遥控另一台映舟」（`remote_page.dart`，`_nowPlaying`、`_textBar` 排在 `_dpad` 前面）同样如此。刚刚用熟的位置一下就变了。

**修法**：遥控页的布局固定不动：

- 方向键、OK、返回 / 主页 / 菜单、播放控制、音量各占固定位置，任何状态都不移动。
- 「正在播放」放进顶部一块固定高度的区域：没在播放时显示"未在播放"，播放时显示片名和细进度条，区域高度不变。
- 输入条浮在「正在播放」上面，不往中间插。

**已修**：网页（`index.html`、`remote.css`、`remote.js`）和应用（`remote_page.dart`）都是这样；手机横过来时「正在播放」只留片名和进度条，放不下时从顶上开始滚动。应用的测试在 `remote_page_test.dart`；网页用演示引擎加脚本扮演的屏幕在浏览器里量过方向键的位置。

### 3.2 遥控之外：网页控制台（已做，2026-11-22；设计说明见 [web-console.md](web-console.md)）

配对之后，手机或电脑浏览器已经拿到了和引擎说话的令牌。电视上不方便做的事，应该能在这个网页上做，而不只是一个模拟的遥控器。

**已经能做的底子**：配对设备的令牌可以访问引擎的全部接口（`AccessPlugin.kt`，只有"管理共享"留给本机），订阅、配置、站点、历史、收藏、设置的接口都在。缺的是**客户端这一侧的数据**：日志（`DevLog`，在内存里）和崩溃记录（存在应用自己的目录里）不在引擎上。

**页面**（同一个网址，手机上是底部标签，电脑上是左侧导航加宽屏布局）：

| 页 | 内容 | 需要新做的 |
|---|---|---|
| 遥控 | 现在的遥控器，布局固定（3.1） | — |
| 正在播放 | 进度、选集、线路（带测速结果）、倍速、字幕、弹幕；播放信息和链路实时显示 | 屏幕把统计和链路随状态一起发过来 |
| 订阅与站点 | 列出、添加、修改、删除、切换订阅；从手机剪贴板粘一个地址推给电视；重新加载配置；站点列表和可用性 | 只有界面，接口都有 |
| 数据 | 导出 / 导入一个备份文件（订阅、设置、历史、收藏）；管理历史和收藏 | 引擎加导出 / 导入接口 |
| 日志与崩溃 | 客户端日志、崩溃记录、引擎日志，可以筛选；**下载为文件**；「生成反馈」把完整内容（不截断）带到手机浏览器里的 GitHub 新问题页 | 屏幕按请求把日志和崩溃记录发过来；引擎日志接口（路线图里已有） |
| 设置 | 一部分适合远程改的：网络代理、弹幕默认值、用法 | 只有界面 |

**电视崩溃日志怎么导出来**：这一项解决的就是这个问题。现在电视上只能「复制诊断信息」（复制到电视的剪贴板，没地方粘）或扫一个二维码（装不下全部内容，只带开头）。有了控制台：手机扫电视上显示的配对二维码 → 打开「日志与崩溃」→ 下载或直接生成反馈。

**客户端数据怎么到网页上**：屏幕（应用）本来就通过遥控的 WebSocket 连着引擎。加一种请求"把诊断信息给我"：网页发给引擎，引擎转给屏幕，屏幕把脱敏后的日志和崩溃记录发回来。这样不管引擎在电视里（安卓内置引擎）、在电脑上还是在 NAS 上，都走同一条路。

**安全**：只对配对过的设备开放（现有规则）；离开设备之前照样遮掉订阅地址、令牌、签名参数和用户目录；导入备份前先显示里面有什么，确认后才写入；电视上的「局域网」里能看到哪些设备配对过、随时取消。

## 5. 怎么验证

- **焦点**：电视播放页每个面板、拨盘、信息条，四个方向各按到头再多按三次：焦点不离开当前层、进度不变、同时最多一个面板。写成测试。
- **按键数**：用流程分镜（[design-lab.md](../design-lab.md)）数几件常做的事要按几下，改之前和改之后各数一次：换倍速、开关弹幕、换线路、选第 12 集、看播放信息、退出播放。
- **遥控页**：未播放、播放中、屏幕上有输入框三种状态下截图，方向键的位置像素级不变。
- **真机**：电视遥控器（有菜单键和没有菜单键的各一个）、手机浏览器连电视、电脑浏览器打开控制台。
