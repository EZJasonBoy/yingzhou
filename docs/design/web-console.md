# 设计说明：网页控制台

> 状态：✅ 已做（v0.4.146825098），五页都在 `engine/api/src/main/resources/remote/`（`pages/*.js` 按需加载）；客户端的命令在 `client/lib/remote/remote_diagnostics.dart`、`remote_app_settings.dart`，备份接口在 `engine/api/.../BackupRoutes.kt`。和下文不同的地方：设置多了一项 `remote.screenName`（屏幕改名）；开关读出来是布尔值，写的时候布尔值和 `"true"` / `"false"` 都收；管理别的配对设备不在网页上做（令牌列不出它们）；收藏只显示片名；只有深色。来由见 [ux-review.md](ux-review.md) 的 3.2；样子见[原型](prototypes/README.md)里「网页控制台」那一排画板。

## 要解决什么

电视上不方便做、甚至做不了的事：

- **导不出日志**：电视盒子崩溃后，「复制诊断信息」复制到的是电视自己的剪贴板，没地方粘；二维码装不下全部内容，只带开头；很多电视没有浏览器。
- **打字和粘贴**：订阅地址又长又没规律，用遥控器一个字一个字按。
- **文件**：导入导出配置、观看记录，电视上没有文件管理器可用。
- **看长内容**：链路、日志在十英尺外看不清，也不好翻。

配对之后手机或电脑的浏览器已经拿到了和引擎说话的令牌，这些事都应该能在那边做。网页遥控器不该只是一个模拟的遥控器。

## 现状（能直接用的底子）

- 网页遥控器在 `/remote/`，五个静态文件，没有构建步骤，自己配对，令牌存在浏览器里（[protocol.md](../protocol.md)「遥控」）。
- 配对设备的令牌能访问引擎的全部接口，只有 `/api/v1/lan`（管理共享）留给本机（`AccessPlugin.kt`）。订阅、配置、站点、历史、收藏、设置的接口都在。
- 屏幕（应用）经 WebSocket 连着引擎，网页的命令经引擎转给它，它回一个结果。

**缺的**：

1. 客户端这一侧的数据不在引擎上：日志（`DevLog`，内存里最近 500 条）、崩溃记录（应用自己的目录，`diagnostics_store`）、内置引擎的输出（电脑上是 `engine.log`，安卓上是 logcat）。
2. 命令的结果现在只有 `ok` 和一句 200 字以内的 `message`（`RemoteHub.kt` 重新拼的），带不了数据。
3. 应用自己的设置（用法、起始页、弹幕默认值）在客户端里，引擎不知道。

## 结构

还是同一个网址 `/remote/`，同一套配对，页面多几页：

| 页 | 手机 | 电脑浏览器 |
|---|---|---|
| 遥控 | 底栏第一个，布局固定 | 左侧导航第一项「遥控与播放」：遥控器在左边一栏，旁边就是「正在播放」 |
| 正在播放 | 底栏第二个 | 和遥控在同一页 |
| 订阅与站点、数据、日志与崩溃、设置 | 底栏第三个「更多」里的列表；「更多」最上面是「把订阅推给电视」 | 左侧导航各一项 |

- 宽度 ≥ 900px 用左侧导航加宽屏布局，否则底栏。同一份 HTML。
- 仍然不要构建步骤：`remote.js` 留下配对、连接、状态；每一页一个模块文件（`pages/logs.js` …），打开那一页时才加载。`Content-Security-Policy` 不变（只运行自己的脚本）。
- 地址后面可以带页：`/remote/#page=logs`。电视上「设置 → 关于 → 诊断与反馈」显示的二维码就是它（没配对过再带上配对码）。

## 第一页：日志与崩溃

### 屏幕回传数据

命令照旧经引擎转给屏幕；**结果多一个可选的 `data`**（JSON 对象），引擎原样转给发命令的那个遥控端。屏幕发来的消息上限是 512 KB，够用；超过就分页。这是引擎唯一要改的地方（`RemoteHub.Screen.receive` 里拼 `result` 的那几行），老的遥控端看不到 `data` 也不受影响。

| 命令 | 参数 | `data` |
|---|---|---|
| `diag.summary` | — | `{app:{version, platform, form}, engine:{version, kind}, crashes:[{id, time, source, title, repeated}], logCount, hasEngineLog}` |
| `diag.log` | `{after?: 序号, limit?: 200}` | `{entries:[{seq, time, level, module, message, detail}], next}`：从 `after` 之后的，最多 `limit` 条 |
| `diag.crash` | `{id}` | `{text}`：这一条崩溃记录的全文 |
| `diag.engineLog` | `{lines?: 300}` | `{text}`：内置引擎输出的最后几行（电脑上读 `engine.log`，安卓上读 logcat）；连的是别处的引擎时 `hasEngineLog=false` |
| `diag.report` | — | `{text}`：和「复制诊断信息」相同的全文，不截断 |

- 这些命令由应用这一层处理（`remote_agent.dart` 的 `perform`），不依赖正在哪个页面。
- **离开设备之前先脱敏**：屏幕用 `Diagnostics.redact` 遮掉订阅地址、令牌、签名参数和用户目录之后才发。网页拿到的就是能直接贴出去的内容。
- 实时：页面开着时每 2 秒问一次 `diag.log`（带 `after`），有新的就接上。不做推送，省得改状态协议。

### 页面

- 顶上一行：哪块屏幕、什么版本、什么系统；「下载全部」「生成反馈」。
- 「崩溃记录」：最近的几条，每条一行（时间、来源、第一句），点开看全文，可以单独复制、下载。
- 「日志」：级别筛选（全部 / 信息 / 警告 / 错误）、搜索、实时跟随；点一条在旁边（手机上是下面）看细节。
- 「引擎输出」：有的话，最后 300 行。
- **下载**：把 `diag.report` 的全文存成 `yingzhou-诊断-<日期>.txt`（浏览器里拼一个 Blob 存下来，不经过任何服务器）。
- **生成反馈**：打开 GitHub 新问题页，填好版本和系统；全文同时复制到这台手机的剪贴板，页面上提示"粘贴到「诊断信息」一栏，或把刚下载的文件拖进去"。手机有浏览器、有剪贴板，电视上那两个堵点都没了。

### 电视这一侧

- 「诊断与反馈」页的二维码换成指向 `/remote/#page=logs`，旁边写"用手机查看、下载和反馈"。原来的「复制诊断信息」留着（电脑上有用）。
- 要先打开「允许手机遥控」：没打开时这里给一个开关，而不是让人去设置里找。

### 做不到的

应用一启动就崩，屏幕连不上引擎，网页就拿不到任何东西（安卓上内置引擎和应用是同一个进程）。崩溃记录是存在设备上的，下一次能启动时还在。连续启动失败的情况这一版不解决，在页面的空状态里写明。

## 其余几页

| 页 | 做什么 | 用哪些已有接口 | 要新做的 |
|---|---|---|---|
| 正在播放 | 进度、选集、线路（带体检结果）、倍速、字幕、音轨、弹幕；播放信息；开发者模式下的链路 | 屏幕状态里的 `player` 和现有命令 | 状态里加 `player.info`（清晰度、网速、缓冲、来自哪、换过的线路；就是应用里「播放信息」那几项）；开发者模式再加脱敏后的 `player.chain`；线路带体检结果（见 [line-probe.md](line-probe.md)） |
| 订阅与站点 | 列出、添加、改名、删除、切换订阅；粘贴一个地址推给电视；重新加载；站点列表 | `/subscriptions`（增删改、`activate`）、`/config`、`/config/reload`、`/sites` | 只有页面 |
| 数据 | 导出一个备份文件，导入前先看里面有什么；管理观看记录和收藏 | `/history`、`/favorites` | 引擎加 `GET /api/v1/backup`（订阅、引擎设置、历史、收藏，一个 JSON）和 `POST /api/v1/backup?dryRun=1`（只回答会改什么）/ `POST /api/v1/backup`（写入）；应用自己的设置第二步再加（经命令 `settings.export` / `settings.import`） |
| 设置 | 适合远程改的几项：GitHub 镜像、HTTP 代理、安全 DNS；用法、起始页、弹幕默认值 | `/settings`、`/github-proxy`、`/network` | 应用的设置经命令 `setting.get` / `setting.set`，只开放一份白名单里的键；简单模式上了锁时要先在网页上输同一个 4 位密码 |

每页"做完"的标准：

- **订阅与站点**：手机上粘贴一个订阅地址，电视首页在 5 秒内换成新订阅的站点；删掉正在用的订阅时先问一句。
- **正在播放**：电视上换线路、换集，网页 1 秒内跟上；网页上换，电视跟上。
- **数据**：从一台设备导出，在另一台导入，订阅、历史、收藏都在；导入前的清单和实际写入的一致；备份文件里的订阅地址是明文，页面上写明"这个文件里有你的订阅地址"。
- **设置**：改了代理，应用里的「设置 → 网络」显示同样的值。

## 安全

- 只对本机和配对过的设备开放（现有规则），电视上「局域网」里能看到配对过哪些设备、随时撤销。
- 日志和崩溃记录先脱敏再离开设备；备份文件不脱敏（要能还原），导出时明说。
- 导入、删除订阅、改设置这类会改东西的操作，网页上都要点一次确认；命令带上是哪台设备发的，屏幕上出一条提示"手机「xx」导入了订阅"。
- 和局域网共享一样没有 TLS：只在自己的局域网里用。

## 不做

- 不控制电视的系统（音量键、开关机），不传文件到电视的存储里。
- 不做账号、不做外网访问。
- 不在网页里播放视频。

## 怎么验证

- **引擎测试**：`result` 带 `data` 时原样转给发命令的那个遥控端，别的遥控端收不到；超过上限的消息照旧断开。
- **客户端测试**：五个 `diag.*` 命令的回答；回答里没有订阅地址、令牌和用户目录（用 `diagnostics_redact_test` 里的同一批样本）。
- **网页**：用演示引擎加脚本扮演的屏幕，在手机尺寸和电脑尺寸各走一遍（和遥控页布局那次同样的办法）；下载下来的文件和 `diag.report` 的全文一致。
- **真机**：安卓电视盒子上制造一次崩溃，重新打开后用手机扫码，把记录下载下来；没配对的手机打开同一个地址只看到配对页。

## 分几步

1. 引擎：`result` 转发 `data`；测试。
2. 客户端：`diag.*` 命令；「诊断与反馈」页的二维码。
3. 网页：页面框架（底栏「更多」、宽屏的左侧导航）和「日志与崩溃」页。
4. 之后每页一步，顺序：订阅与站点 → 正在播放 → 数据 → 设置。
