# 设计

映舟的界面和交互怎么定、怎么做、怎么验证。

| 目录 / 文件 | 是什么 |
|---|---|
| [system/](system/README.md) | 设计系统「夜航」：总则、语气、颜色、字、间距、形状、焦点、动效、图标、四种设备，十个组件各有说明和预览页 |
| [tokens.json](tokens.json) | 设计系统的唯一来源：两个主题的颜色、字号、间距、圆角、阴影、尺寸。改了运行 `node tools/design/gen-tokens.mjs` |
| [prototypes/](prototypes/README.md) | 界面原型：三种用法（简单、标准、开发者）、电视播放页的拨盘、网页控制台；图片、可点的网页和画布源文件 |
| [ux-review.md](ux-review.md) | 界面与交互梳理：三种用法该怎么分、电视播放页的焦点和按键、网页遥控器和网页控制台，哪些做了、哪些排在后面 |
| [line-probe.md](line-probe.md) | 设计说明：线路体检（先测再播、换线路时不干等），下一版做 |
| [web-console.md](web-console.md) | 设计说明：网页控制台（第一页「日志与崩溃」下一版做，其余几页排在后面） |
| [../design-lab.md](../design-lab.md) | 工作流：设计台（四种设备并排的真实应用）、流程分镜（数步数）、界面巡览（三种尺寸的截图） |

一个新界面的顺序：先对一遍[交互的七条规则](system/README.md)，写清楚任务和步数，在原型里试，再写进代码，最后在设计台和流程分镜里验证。大一点的功能先写一页设计说明（要解决什么、几种做法、选哪个、怎么验证），放在这个目录里。
