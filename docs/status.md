- 嗅探：Windows 上的 Edge，Android 模拟器上的 WebView。
- `/m3u8` 去广告与主播放列表转发，经引擎代理后可播（ffprobe）。

### 真实订阅体检（2026-11-13）

用 `tools/check-configs.sh` 对 `tvbox-ysc-config/output` 里的配置跑了**采集站、远程站和直播**（`ONLY=cms,remote,live`）：

> 更正（2026-11-16）：这一轮本意是不运行蜘蛛代码，但当时的工具有漏洞——「小马」配置里有四个直播源经 `127.0.0.1:9978/proxy` 取列表，引擎为此加载了该配置的全局 jar 并执行了它的初始化（加载它自带的原生库时失败）。已在 `03facf0` 修复：范围里没有 `jar` / `js` 时不再注册对应的运行时。

- 多仓、多仓里套多仓（拾光多仓、挺好分享多仓）都能逐个加载；加载失败的条目都是地址自己失效（域名不存在、401/403/404、域名停放页）。
- 采集站能访问的全部通过"首页 → 分类 → 详情"；失败的是域名解析不了、超时、返回非 JSON 的停放页。
- 直播：TXT / M3U 列表正常解析（最大的一个 8252 个频道）；失败的是 404、域名不存在、列表为空、配置里把地址写错（`https://https://…`）。
- 由此修掉的引擎问题：证书校验比 TVBox 严、不认 JSON 列表、不认 `127.0.0.1:9978/proxy` 形式的列表地址、多个节目单地址只试第一个。

**jar / JS 蜘蛛站点（占真实配置的九成）要由使用者自己运行体检**：`tools/check-configs.sh`。它会在本机执行订阅里的蜘蛛代码，报告里"引擎兼容"一栏就是接下来要修的清单。

## 已知缺口

按对桌面用户的影响大致排序：

1. **点播没有自动换源**：一部片的线路全部失效时，不会去别的站点找同名的片接着播（TVBox 的"换源"，站点的 `changeable` 也还没用上），要自己搜。同一部片内的自动换线路已经有了（2026-11-18）：解析失败、播放器打不开、15 秒没有画面、播到一半断开，都会带着进度换到下一条有这一集的线路，每条只试一次；手动选的线路不会被自动换走。它判断不了的情况：线路能播但内容不对（别的片、别的集）、清晰度差、只是卡顿——这些仍然要手动换。
2. **字幕、弹幕**：都没做。
3. **`hosts` / DoH 管不到播放器**：引擎发出的请求都走它们，但播放器（libmpv）自己取媒体流时用系统 DNS，靠 `hosts` 改 CDN 地址的直播频道可能仍然打不开。
4. **Python 蜘蛛直播**：jar / JS 蜘蛛直播已支持。
5. **加固 jar**（带 native 壳）在桌面上跑不了；Android 上可以。
6. **Python 蜘蛛**：调研的公开配置里只有个别站点用。
7. **站点 `style`**：海报比例等没按配置来。
8. **局域网共享只在一台机器上测过**：配对、令牌、签名地址都有测试，但没有在真正的第二台设备上播放过；没有扫码配对，也没有 TLS。演示站的海报地址指向本机，在第二台设备上不显示。
9. 协议文档里的 `/events`（WebSocket）、`/danmaku` 尚未实现。
10. **Docker 镜像没有构建过**：Dockerfile、compose 和 CI 已写，镜像里用的 Java 参数和模块已在本机验证，但镜像本身没有在 Docker 里构建或运行。
11. **安装程序没有数字签名**，下载后第一次运行会被 SmartScreen 拦一下；也没有自动更新，升级要手动下载新安装包。

遇到某个订阅不能用时，先对照 [compatibility.md](compatibility.md) 看是不是已知缺口。
