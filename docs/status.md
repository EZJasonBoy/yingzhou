## 已知缺口

按对桌面用户的影响大致排序：

1. **点播没有自动换源**：一部片的线路全部失效时，不会去别的站点找同名的片接着播（TVBox 的"换源"，站点的 `changeable` 也还没用上），要自己搜。同一部片内的自动换线路已经有了（2026-11-18）：解析失败、播放器打不开、15 秒没有画面、播到一半断开，都会带着进度换到下一条有这一集的线路，每条只试一次；手动选的线路不会被自动换走。它判断不了的情况：线路能播但内容不对（别的片、别的集）、清晰度差、只是卡顿——这些仍然要手动换。
2. **`hosts` / DoH 管不到播放器**：引擎发出的请求都走它们，但播放器（libmpv）自己取媒体流时用系统 DNS，靠 `hosts` 改 CDN 地址的直播频道可能仍然打不开。
3. **加固 jar**（带 native 壳）在桌面上跑不了；Android 上可以。
4. **Python 蜘蛛只在演示蜘蛛上验证过**；Docker 镜像里没有 Python，NAS 上 Python 站点打不开；"下载 Python 运行时"和装包只用本地模拟的服务器测过。
5. **网盘**：只测了演示 WebDAV、本机文件夹和模拟的 AList；不能下载网盘里的文件（本来就是自己的文件），网盘里的 m3u8 在局域网设备上播不了。
6. **离线下载**：桌面上的导出只经接口测过，没有在真实应用里点过；安卓上下载、导出、分享在模拟器上点过，离线播放只验证到引擎这一步。
7. **站点 `style`**：海报比例等没按配置来。
8. **局域网共享只在一台机器上测过**：配对、令牌、签名地址都有测试，但没有在真正的第二台设备上播放过；没有扫码配对，也没有 TLS。演示站的海报地址指向本机，在第二台设备上不显示。
9. 协议文档里通用的 `/events`（WebSocket）尚未实现；目前用到 WebSocket 的只有遥控器（`/api/v1/remote/…`）。
10. **Docker 镜像只在 CI 里验证过**（构建、启动、配对码、演示自检都通过），没有在 NAS 上实际跑过。原先的说明：Dockerfile、compose 和 CI 已写，镜像里用的 Java 参数和模块已在本机验证，但镜像本身没有在 Docker 里构建或运行。
11. **安装程序没有数字签名**，下载后第一次运行会被 SmartScreen 拦一下。能检查更新并把安装包下好，但安装还要自己运行（不会自动替换）。
12. **安卓**：没有 Python 蜘蛛；检查更新只是用浏览器打开 APK 下载；手机手势只在模拟器上验证过（电视盒子已在真机上试过）。
13. **遥控器**：不控制操作系统的鼠标键盘、系统音量，不能唤醒或关机；没有 TLS（和局域网共享一样）；手机端「找片、在大屏上播」还没做。

遇到某个订阅不能用时，先对照 [compatibility.md](compatibility.md) 看是不是已知缺口。

1. 用真手机试遥控（iPhone 的 Safari、安卓的 Chrome 和映舟应用），以及真手机上的安卓版。
2. 体检剩下的配置；查返回为空的 jar 站点（需要带引擎日志再跑一次）。
3. 下一版发布时，用装好的 v0.4.0 检查一次更新（直连、经加速代理各一次）。
4. 在真正的 Linux 桌面上试 Linux 版；在 NAS 上验证 Docker 镜像。
5. 点播自动换源（线路全失效时搜其他站点的同名片）；遥控器的「找片」投送。
