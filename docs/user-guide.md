# 使用说明（桌面版）

> 针对 Windows 版；macOS 版操作相同，Ctrl 换成 ⌘。

## 1. 安装与启动

两种包，内容一样，任选其一：

**安装程序**（推荐）：运行 `yingzhou-windows-x64-setup.exe`，一路"下一步"。

- 只装给当前用户，不需要管理员权限，默认装到 `C:\Users\<你>\AppData\Local\Programs\Yingzhou`，可以改。
- 装完在开始菜单里有「映舟」，安装时可选是否放桌面快捷方式。
- **升级**：直接运行新版安装程序，会装到原来的位置，订阅和记录都保留。
- **卸载**：「设置 → 应用」里找到「映舟」卸载。卸载时会问要不要一并删除订阅、观看历史、收藏和设置，默认保留。
- 安装、升级、卸载前要先关掉映舟，否则会提示你关闭。
- 安装程序没有数字签名。从网上下载的安装包第一次运行时，Windows 可能弹出"Windows 已保护你的电脑"，点"更多信息 → 仍要运行"。

**绿色包**：解压 `yingzhou-windows-x64.zip` 到任意目录（路径里最好没有特殊字符），运行 `yingzhou.exe`。要"卸载"就删掉解压目录；想清掉订阅和观看记录，再删 `C:\Users\<你>\.tvbox-next` 和 `C:\Users\<你>\AppData\Roaming\Yingzhou`。

不需要另装 Java 或播放器，引擎、Java 运行时、libmpv 都在包里。启动时界面会显示"正在启动内置引擎…"，几秒后进入首页。关闭窗口时引擎一起退出。

## 2. 界面

窗口左侧（窗口窄时在底部）是五个入口：

| 入口 | 做什么 |
|---|---|
| **首页** | 选一个站点，看推荐、按分类和筛选浏览 |
| **直播** | 电视直播和节目单 |
| **搜索** | 所有站点同时搜一个片名 |
| **我的** | 观看历史、收藏 |
| **源** | 引擎连接、订阅、站点列表 |

## 3. 导入订阅

第一次打开时首页会提示"先在'源'里导入订阅"。

1. 进「源」页，在"订阅地址"里粘贴地址，点"导入"。支持 `http(s)://`、`clan://`、`file://`、带 `;pk;密钥` 后缀的加密订阅，也可以直接填本机上配置文件的路径（如 `C:\tv\my.json`）。
2. 如果是多仓订阅，会出现"选择仓库"，挑一个。条目本身又是多仓的（标着"（多仓）"），选中后会展开，它里面的条目缩进显示在下面，并自动加载其中第一个能用的。
3. 导入成功后"当前配置"显示站点、解析、直播的数量，下面列出所有站点和它们的类型。

「源」页的「网络」里有一个 **GitHub 加速代理**开关，默认关闭：这时放在 GitHub 上的订阅和文件直接从 GitHub 获取，订阅里自带的 `gh-proxy` 之类的前缀会被去掉。直连 GitHub 很慢或打不开时再打开它，并填一个你那里能用的代理地址。切换后当前订阅会立即重新加载，「当前配置」下面会显示实际访问的地址。

「网络」里还有 **安全 DNS（DoH）**，默认"关闭（系统 DNS）"。有些网络会把影视站的域名解析到错误的地址（表现为站点打不开、订阅加载失败），这时可以选一个服务商（腾讯、阿里、360、Google、AdGuard、Quad9，以及当前订阅自己提供的），引擎就改用它查域名。要知道的是：打开后，引擎要访问的每个域名都会发给你选的那个服务商；订阅只能提供可选项，不能替你打开。选了之后马上生效，不用重新加载订阅；它连不上时会自动退回系统 DNS，并在下面提示一行。

订阅如果自带网络规则（`hosts` 域名重定向、`headers` 请求头、`ads` 嗅探屏蔽），「网络」底部会写出各有几条，点"查看"能看到具体内容。这些规则随订阅生效，切换订阅就换成新订阅的。

可以导入多个订阅并随时切换。当前用的订阅会记住，下次启动自动加载：引擎先用上次保存的那份订阅直接进首页，不用等下载，同时在后台获取最新的——内容有变化就自动换上，没变化就什么都不动。订阅地址暂时连不上也不影响使用，「当前配置」下面会写明"用的是某时保存的副本"和原因。想马上获取最新的订阅，点「当前配置」里的 **刷新**。

站点的首页、分类和详情也会保存一段时间（首页和分类 15 分钟，详情 1 小时），所以第二次打开是立刻显示的；过了时间再打开，先显示旧的，后台取到新的后下次就是新的。想立刻看到最新内容（比如追更新），点首页站点名右边或详情页右上角的 ⟳。海报图片保存在本机，看过的不会再下载。断网时，看过的页面和海报照样能翻，搜索和播放不行。

「源」页底部的 **缓存** 一栏显示这些内容占了多少空间，可以一键清除。占用有上限（站点数据约 50 MB、海报 300 MB），旧的会自动清掉。清除后第一次启动要重新等订阅下载。播放缓存不在这里。

### Python 站点

订阅里有些站点（站点列表里标着 **PY**）和直播源是用 Python 写的，要用电脑上的 Python 3.8 或更新的版本来运行。映舟不自带 Python，「源」页的 **Python 蜘蛛** 一栏写着现在用的是哪个：

- 电脑上已经装了 Python（python.org 的安装包、Microsoft Store、scoop、Homebrew 都行）：自动找到，什么都不用做。装在别处的，在"Python 位置"里填 `python.exe`（或它所在的文件夹）再点"应用"。
- 没有 Python（Windows）：点 **下载 Python 运行时**。确认框里写着从哪里下载（python.org）、多大（约 12 MB）、放在哪里，确认后才开始下载；它只给映舟用，不装进系统、不改环境变量，以后可以在同一处删除。macOS 请自己装 Python 3（python.org 的安装包或 Homebrew），装好后点这一栏右上角的刷新。
- **安装常用依赖**：大部分 Python 站点还要用到 `requests`、`lxml` 等第三方包。点这个按钮，映舟会用 pip 把 TVBox 的 Python 版自带的那几个包（requests、lxml、pycryptodome、beautifulsoup4、pyquery、ujson、jsonpath、cachetools）装到映舟自己的目录里，不会动你电脑上 Python 自己的环境。确认框里写着从哪里下载、装到哪里。某个站点打开时提示"缺少 Python 包 xxx"，这一栏也会列出来，旁边有"安装 xxx"按钮。
- 下载慢的话，在"镜像"里填国内的 PyPI 镜像（如 `https://mirrors.aliyun.com/pypi/simple/`）或 Python 下载镜像（如 `https://mirrors.huaweicloud.com/python/`）。下载的 Python 会按 python.org 公布的校验值检查，用镜像也一样。

Python 站点和其他站点一样浏览、搜索、播放；Python 直播源也和其他直播源一样在「直播」页里。没有 Python 时，这些站点在「源」页标着"需要 Python"，直播源标着"（需要 Python）"，打不开但不影响其他站点。

## 4. 看片

1. 「首页」选站点 → 点海报进详情页。
2. 详情页选线路和集数，点"播放"。看过的会显示"继续播放 第 N 集 mm:ss"，旁边可以"从头播放"。点 ♡ 收藏。
3. 播放页点右下角的"选集"，侧栏里可以选集和换线路。右上角显示当前线路，以及它是怎么解析出来的（经某个解析接口、网页嗅探；直链不标）。

### 线路放不了时

一部片通常有好几条线路，其中一些可能已经失效。当前线路放不了时，播放页会自己换到下一条：

- **什么算放不了**：播放地址解析失败；播放器打不开；15 秒没有画面；播到一半断开（离片尾还远就结束了）。
- **怎么换**：按线路顺序往后找有这一集的线路，到头再从第一条接着找，每条只试一次。画面中间会提示一句，例如"「线路一」解析失败，已切到「线路二」"，右上角的线路名跟着变。
- **进度不丢**：从已经播到的位置（刚打开时是历史记录里的位置）接着播，不会回到开头。
- **全部都不行**：停在你原来选的线路上，显示最后一条线路的失败原因，下面有"重试"（按同样的顺序再来一轮）和"换线路"（打开侧栏自己挑）。
- **手动选的线路不会被换走**：你在侧栏里亲手换的线路，就算放不了也只提示，不会自动跳到别的线路；换到下一集后恢复自动。手动换线路同样从当前进度接着播。

它只能发现"放不了"。线路能播但内容不对、清晰度差或只是卡顿时，还是要自己换。所有线路都失效时也不会自动去别的站点找同一部片，用「搜索」找其他站点的同名片。

找片更快的办法是「搜索」（Ctrl+F）：输入片名回车，所有可搜索的站点同时搜，结果边到边出，顶部可以按站点过滤。

### 进度条与播放缓存

很多线路是 m3u8 流，片源又慢，拖一下进度条就要重新下载、卡很久。映舟把看过的和预读的部分存下来，拖动时尽量不再去片源取：

- **拖动进度条**：按住拖的时候画面不动，进度条上方显示松手后会跳到的时间；**松手才跳，只跳一次**。鼠标悬在进度条上也会显示那一处的时间。← / → 连按会累加，连按三下就是 30 秒。
- **进度条上的浅色段**是已经缓存好的部分，跳到这些位置基本不用等（零点几秒）。
- **m3u8 视频**（大多数线路）由引擎代为下载，存在磁盘上：
  - 看过的部分一直留着，往回拖多远都不用重新下载；
  - 当前位置之后会提前下载好一段：刚开始播或刚跳转时是半分钟，连着往下看就逐步加到约三分钟；最多 4 个连接同时下，片源越慢越有用；
  - 跳到完全没缓存的位置时，那一小段拆成几块同时下载，比以前快一倍左右（取决于片源）；
  - 关掉这一集再打开、第二天接着看，缓存都还在。
- **其他直链视频**（mp4、flv、mkv 等）由播放器自己缓存到一个临时文件：这一集开着的时候，播过和预读（约五分钟）的部分都能随时跳回去；关掉这一集，临时文件就删掉。
- **占多少磁盘**：m3u8 的缓存默认最多 2 GB，放满后自动删掉最久没看的部分。在「源」页的「播放缓存」里可以看占用、改上限、清空，或者整个关掉。直播不缓存。

缓存帮不上的情况：第一次跳到一个没缓存的位置，仍然要现下载，快慢取决于片源；片源本身就打不开时，缓存也没有用（见上面的"线路放不了时"）。

## 5. 看直播

「直播」页从左到右是：分组 → 频道（带当前节目和进度条）→ 播放器，播放器下面是当天的节目单，正在播的那条高亮（能回看的频道还可以选前几天，见下面"回看"）。订阅里有多个直播源时可在顶部切换。

| 按键 / 鼠标 | 作用 |
|---|---|
| ↑ / ↓ | 上一个 / 下一个频道（会跨分组） |
| ← / → | 上一条 / 下一条线路；回看时是快退 / 快进 |
| PageUp / PageDown | 上一个 / 下一个分组 |
| F / 双击画面 | 全屏；全屏时动一下鼠标或按键，频道列表会浮出来 |
| Esc | 退出全屏；回看时回到直播 |
| M / 滚轮 | 静音 / 音量 |
| 空格 | 暂停、继续 |

### 回看

能回看的频道（订阅里给了回看规则），节目单上方会多出一排日期：「今天」「昨天」「前天」……往前最多到这个频道允许的天数。

- 已经播完的节目后面标着「回看」，点一下就从头播放这个节目；正在播的节目只回看到现在。
- 回看时频道名旁边和画面左上角都有橙色的「回看」标记，下面有进度条可以拖动，←/→ 快退 / 快进 10 秒（按住 Shift 是 60 秒），空格暂停。
- 「回到直播」按钮、Esc，或者点节目单里「直播中」的那条，回到直播；换台也会回到直播。
- 不能回看的频道和以前一样：没有日期，节目单只是看看。
- 回看地址打不开时会提示"这个节目可能已经不能回看了"——源站一般只保留几天的录像，太早的节目往往已经删了。

- 一条线路打不开，或 15 秒没有画面，会自动换下一条；全部试过都不行才提示。
- 记住上次看的频道，下次进「直播」直接播它。
- 离开「直播」页就停止播放。
- 频道列表缓存半小时，点"刷新频道"可立即重新拉取。

## 6. 我的

- **观看历史**：点一条回到详情页，从上次的位置继续。可以清空（会清掉所有设备上的记录，因为数据在引擎里）。
- **收藏**：在详情页点 ♡ 加入。

## 7. 连另一台设备上的引擎

引擎可以给同一网络里的其他设备用（比如家里常开的电脑或 NAS），其他设备的客户端连它，订阅、历史、收藏、进度就都是同一份。别的设备要先**配对**一次。

**在提供引擎的电脑上**（装着映舟的那台）：

1. 「源」页的「局域网」里打开 **局域网共享**（默认关闭）。Windows 第一次会问是否允许 Java 通过防火墙，选"专用网络"允许。
2. 下面会显示其他设备用的地址（如 `http://192.168.1.5:9978`）和一个 6 位 **配对码**。配对码 10 分钟内有效，用过一次就作废，"换一个"可以立即换。
3. 配对过的设备列在下面，显示最后一次使用的时间和地址，点"撤销"它就不能再用了，引擎发给它的播放地址也随之失效。
4. 关掉开关，引擎立即停止在网络上监听，所有设备都连不上了；再打开，已配对的设备不用重新配对。

**在要连接的设备上**：

1. 「源」页「局域网」里点"发现局域网里的引擎"的 **搜索**，列表里点那台引擎；也可以在上面"引擎地址"里直接填地址，点"连接"。
2. 弹出「与引擎配对」，输入那台电脑上显示的配对码，点"配对"。之后这台设备会记住，下次直接连上。
3. 想断开：「局域网」里点"取消配对"，或者在提供引擎的电脑上撤销它。

**NAS / 没有界面的引擎**：用 `--lan` 启动（Docker 镜像默认如此，见第 8 节），配对码打印在引擎的日志里；在要连接的设备上打开配对窗口时，日志里会出现新的配对码。

说明：

- 配对码连续输错 5 次，所有设备的配对会暂停 1 分钟（再错就 2 分钟、4 分钟……最长 15 分钟），引擎换一个新码。
- 配对窗口提示"令牌无效或已被撤销"说明这台设备已被撤销或引擎的数据被清掉了，重新配对即可。
- 只在信任的网络里打开共享：配对挡住了不知道配对码的人，但传输没有加密（HTTP），同一网络里能抓包的人能看到你在看什么。
- 自动发现需要两台设备在同一个网段、路由器不拦组播；找不到时直接填地址一样能用。

## 8. 在 NAS 上运行引擎（Docker）

> **这个镜像还没有实际构建、运行过**：写它的开发机上没有 Docker。Dockerfile、compose 文件逐行检查过；镜像里用的引擎参数、JVM 参数和 Java 模块列表在 Windows 上跑通了演示自检，`--lan` 模式打印配对码、拒绝无令牌请求也试过。仓库推到 GitHub 后，`.github/workflows/engine-image.yml` 会构建镜像、启动它并做同样的检查。第一次在 NAS 上构建时仍可能遇到问题，欢迎反馈。

NAS（群晖、威联通、Unraid、任何装了 Docker 的 Linux）上常开一个引擎，家里所有设备连它，订阅、历史、收藏、进度都是同一份。镜像支持 x86（amd64）和 ARM（arm64）。

1. 把仓库的 `engine` 目录放到 NAS 上，在里面运行：

   ```bash
   docker compose up -d --build    # 第一次构建要几分钟：下载 Gradle 和依赖、编译引擎
   docker compose logs -f          # 看配对码
   ```

2. 日志里会出现 `配对码：123456（…前有效）`。日志里同时列出的地址是容器内部的地址，**不用管它**，其他设备用 NAS 自己的地址。
3. 在每台设备的映舟里：「源」→ 引擎地址填 `http://NAS的IP:9978` → 连接 → 输入配对码。配对码过期或用掉了：在设备上重新打开配对窗口（「源 → 局域网 → 输入配对码」），日志里会出现新的码。

说明：

- **数据**（订阅、历史、收藏、已配对的设备、jar 和转换缓存）在卷 `yingzhou-data` 里，更新镜像不会丢。想用 NAS 上的某个目录：把 compose 里的 `yingzhou-data:/data` 改成 `/volume1/docker/yingzhou:/data`，并先把这个目录的所有者改成 UID 10001（`chown -R 10001:10001 …`），引擎以这个非 root 用户运行。
- **端口**：默认 9978。要换就改 compose 里 `ports` 左边的数字（如 `"19978:9978"`），客户端填新端口。
- **自动发现**：桥接网络里 mDNS 广播出不了容器，客户端"搜索"找不到它，直接填地址即可。想要自动发现，把 compose 里的网络改成 `network_mode: host`（只在 Linux 上有效）并去掉 `ports`。
- **网页嗅探**：镜像里带了 Chromium（无沙盒模式运行，容器里没有它的沙盒需要的用户命名空间）。不需要嗅探的话，在 compose 里打开 `WITH_CHROMIUM: "false"` 再构建，镜像小一半，引擎会报告"不能嗅探"，需要嗅探的线路自动跳过。
- **名字和内存**：`TVBOX_NAME` 是其他设备看到的名字；`TVBOX_MAX_HEAP`（默认 `1g`）限制 Java 堆。
- **从 NAS 本机访问也要配对**：经 Docker 端口映射进来的请求在引擎看来来自网关地址，不算"本机"。
- **健康检查**：镜像每 30 秒访问一次 `/api/v1/info`，`docker ps` 里显示 `healthy`。
- **更新**：`git pull` 后再 `docker compose up -d --build`。

## 9. 常见问题

**启动后提示"无法启动内置引擎"**
提示里带着引擎的最后几行输出。常见原因：安装或解压不完整（缺 `engine` 目录）、9978 端口被别的程序占用、杀毒软件拦截了 `engine\jre\bin\javaw.exe`。

**提示"订阅加载失败"**
多半是网络问题（订阅地址访问不了，或需要代理）。在浏览器里打开订阅地址能看到内容再试；也可以换一个子仓。只有第一次导入、或清过缓存之后才会卡在这里；之后引擎存有订阅的副本，地址连不上也能照常启动。

**站点更新了，这里看到的还是旧的**
站点数据会保存一会儿（见第 3 节）。点首页站点名右边的 ⟳，或详情页右上角的 ⟳，就是现在向站点要最新的。

**订阅作者更新了订阅，这里没变**
每次启动都会在后台核对一次，有变化会自动换上。不想等下次启动就到「源 → 当前配置」点"刷新"。如果那里写着"没能获取到最新的订阅"，下面一行就是原因（多半是订阅地址暂时连不上）。

**订阅里的仓库全是 404，地址里带 gh-proxy**
订阅把一个 GitHub 加速代理写死在了地址里，而那个代理失效了。确认「源 → 网络 → GitHub 加速代理」是关闭的（默认就是），这样会绕过它直连 GitHub。如果你的网络连不上 GitHub，就打开开关并换一个能用的代理地址。

**很多站点都打不开，换了订阅也一样，但别人说能用**
可能是你的网络把这些域名解析错了。到「源 → 网络 → 安全 DNS」选一个服务商再试。没有改善就改回"关闭"。

**订阅里有 hosts，直播频道还是打不开**
`hosts`（域名重定向）目前只对引擎自己发的请求生效：取频道列表、节目单、站点数据都算，但播放器直接去取的直播流不算。靠 `hosts` 换 CDN 才能播的频道暂时还放不了。

**站点能打开，但点进去加载失败或一直转圈**
大多是站点自己失效了，换个站点试试，在安卓 TVBox 上同样会失败。如果安卓上正常、这里不行，查 [compatibility.md](compatibility.md) 里的已知缺口——最常见的是加固 jar（带 native 壳），桌面上还跑不了。

**站点标着"需要 Python"，或者打开时提示"需要 Python 3.8 或更新的版本"**
这是 Python 写的站点，见第 3 节"Python 站点"：电脑上装了 Python 会自动找到；没装就在「源 → Python 蜘蛛」里点"下载 Python 运行时"（Windows），或者自己装一个再点刷新。装好之后不用重启，站点马上能点开。

**打开 Python 站点提示"缺少 Python 包 xxx"**
站点要用一个没装的第三方包。到「源 → Python 蜘蛛」，点"安装常用依赖"，或者点那个包旁边的"安装"。装完马上生效。装不上时点"查看输出"能看到 pip 的原话：常见的是网络连不上 PyPI（在"镜像"里换一个国内镜像），或者这个包没有适合你这个 Python 版本的安装包（换个版本的 Python，或者用下载的运行时）。

**Python 站点提示"Python 进程退出了"**
蜘蛛把运行它的 Python 进程弄崩了（脚本有问题，或者用到的包和这个 Python 版本不兼容）。再点一次会自动重新启动 Python；一直这样就是这个站点在这台电脑上跑不了，换个站点。引擎日志里有 Python 的报错（行首是 `py:`）。

**提示"这条线路需要网页嗅探，但引擎没有可用的浏览器内核"**
嗅探要用系统里的 Edge 或 Chrome。Windows 10/11 自带 Edge；如果装在非标准位置，设环境变量 `TVBOX_BROWSER` 指向浏览器的 exe。还有别的线路时播放页会先自动换过去（提示"需要网页嗅探，已切到…"），都不行才显示这句话。

**播放卡在"正在解析播放地址…"很久**
嗅探类线路要在后台打开网页抓地址，慢的要十几秒。解析失败后会自动换下一条线路；不想等可以点"选集"自己换。

**提示"所有 N 条线路都试过了，都没能播放"**
这部片在这个站点的线路都放不了，见第 4 节"线路放不了时"。可能只是一时的网络问题，点"重试"再来一轮；还不行就用「搜索」换一个站点看。

**拖动进度条后要等几秒才有画面**
跳到的位置还没缓存，要现从片源下载。进度条上浅色的部分是缓存好的，跳到那里不用等；看过的部分都会留着。如果往回拖也要等，看一下「源 → 播放缓存」的开关是不是被关掉了，或者上限是不是设得太小（放满后会删掉最久没看的部分）。个别片源不让引擎代为下载（只认播放器），这时映舟会自动退回"播放器直接取"，拖动就和没有缓存时一样。

**播放缓存占了多少磁盘，怎么清理**
「源 → 播放缓存」里写着已用多少、上限多少，旁边有"清空缓存"。默认上限 2 GB，可以改成 512 MB 到 50 GB。缓存放在引擎所在的那台设备上（见下面"数据存在哪"）；清空或者直接删掉那个文件夹都不影响订阅和观看记录，只是再看时要重新下载。

**关掉播放缓存会怎样**
m3u8 视频改由播放器直接向片源要分片，播放器只在内存里留前后一两分钟；往回拖得远一点、或者片源慢的时候，拖动会明显变慢。一般不需要关，除非磁盘实在紧张，或者某个片源经引擎下载反而出问题。

**播放中间还有广告**
去广告靠订阅里的规则加一个保守的自动判断，宁可漏掉也不误删正片。没去掉说明这个站的广告规则订阅里没有。

**直播页显示"暂不支持"的直播源**
那是配置里写成 `type: 3` 却没有指定蜘蛛的直播源，还没实现。由 jar、JS 或 Python 蜘蛛给出频道列表的直播源是支持的；标着"（需要 Python）"的，见上面"站点标着'需要 Python'"。

**想知道一个订阅里到底哪些站点能用**
运行 `tools/check-configs.sh <订阅地址>`，它会把每个站点、每个直播源试一遍，生成报告 `dist/check-report.md`，并区分是引擎的问题还是站点自己失效。详见 [compatibility.md](compatibility.md) 第 8 节。

**jar 站点全部报 "cant find zipfs support"**
2026-11-13 之前打的包有这个问题（自带的 Java 运行时少了一个模块）。重新打包或换新包即可。

**其他设备连不上我电脑上的引擎**
先确认「源 → 局域网 → 局域网共享」开着、上面列出了地址，两台设备在同一个网络（访客 Wi-Fi 通常和主网络隔离）。Windows 防火墙如果之前点了"取消"，到「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」里给 `javaw.exe` 勾上"专用"。地址显示了好几个（虚拟网卡、VPN）时，用和对方同一网段的那个。

**频道没有节目单**
订阅没给节目单地址，或频道名在节目单里对不上。

**第一次打开某个 jar 站点特别慢**
要先下载 jar 并转换一次（几秒到十几秒），之后有缓存。

**数据存在哪**
订阅、历史、收藏：`C:\Users\<你>\.tvbox-next\engine`。jar 和转换缓存也在这个目录下，删掉会重新下载；订阅副本和站点数据在其中的 `cache\data`。海报图片在 `C:\Users\<你>\AppData\Local\Yingzhou` 下的 `posters` 目录。窗口位置、音量等界面设置在 `C:\Users\<你>\AppData\Roaming\Yingzhou`。这两处都不在安装目录里，所以升级、重装不会丢。

播放缓存（m3u8 视频的分片）在 `C:\Users\<你>\.tvbox-next\engine\cache\stream`，「源 → 播放缓存」里也写着这个位置；它只是缓存，随时可以清空。

Python 相关的都在 `C:\Users\<你>\.tvbox-next\engine\python`：下载的 Python 运行时（`runtime`）、给 Python 站点装的包（`packages`）、Python 蜘蛛脚本（`spiders`）。删掉整个目录不影响别的，只是要重新下载、重新安装。卸载映舟时默认保留它（和订阅、历史一样）。播放直链视频时播放器的临时缓存文件在系统临时目录的 `yingzhou-player-cache` 里，关掉视频就删除（程序异常退出留下的，下次播放时会清掉）。

**安装程序提示"检测到映舟正在运行"**
先关掉映舟的窗口再点"确定"。如果窗口已经关了还提示，在任务管理器里结束 `yingzhou.exe`。

**想给电脑上所有用户安装，或者静默安装**
用命令行运行安装程序：加 `/ALLUSERS` 装到 Program Files（需要管理员权限）；加 `/VERYSILENT` 不显示界面，可再加 `/DIR="D:\Apps\Yingzhou"` 指定位置、`/TASKS=""` 不要桌面快捷方式。
